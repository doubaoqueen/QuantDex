## 2026-10-20

### D-001 影子盘成交口径改为 T+1 两段式
- 改动：收盘挂单（pending）→ 次日开盘价撮合；涨停买不进/跌停卖不出/停牌拒单。
- 原因：原 MVP 用当日收盘价成交，与回测 T+1 口径不一致（轻度未来函数）。
- 验证：49 笔挂单 → 次日开盘全部成交，净值 993,674.68；幂等重跑零重复。
- 复核：2026-11-20（影子盘满 4 周后做偏差归因）。

### D-002 费用模型补齐
- 改动：新增最低佣金 5 元/笔、过户费 0.001%；日报加"今日费用"汇总。
- 原因：外部评审指出最低佣金未建模（对小资金影响巨大：2000 元账户 3 笔 = 0.75%）。
- 验证：大账户现金恒等式差额 0.00；回测成本 119,372 元 / 8.7 年（≈1.2%/年）。
- 复核：2026-11-20。

### D-003 组合回测保真约束
- 改动：涨停买不进/跌停卖不出（收盘涨跌幅近似，容差 ±0.6%）、停牌跳过；分红参数接口保留。
- 原因：原回测假设"任何价位都能成交"，高估收益。
- 结果：总收益 +31.67%（旧 +29.91%）；跳过 5 笔；年换手 1216%（成本拖累明显）。
- 遗留：分红数据待抓（脚本 12）；涨跌停建议改用开盘价判断。
- 复核：2026-11-20。

### D-004 walk-forward 用保真口径重跑
- 改动：06 脚本传 min_fee/transfer_fee/limit_skip/init_capital。
- 结果：OOS +44.50%（旧 +43.19%），年化 8.26%，IR 0.87，MDD -17.16%；参数 5 折中 4 折选 Top50/20日。
- 解读：结果对保真成本不敏感 → 策略绩效不是靠"少算成本"撑起来的。
- 复核：2026-11-20。

### D-005 市值中性化检验
- 改动：新增 scripts/11_neutralize_factors.py；市值代理 = 成交额/(换手率/100)。
- 结果：turnover_20 中性化后 IC -0.0499（t=-2.23，原 -0.0611/-2.55）；vol_20 -0.0466（t=-2.06）；amihud 由 -0.006 翻正 +0.022（t=+1.56）。
- 解读：低换手/低波不是纯小盘代理，方向存活但幅度减弱；amihud 的"溢价"是市值掩盖。
- 遗留：行业中性化（baostock 行业接口在本机挂起，待换源）。
- 复核：2026-10-27。

## 2026-10-21

### D-007 分红口径：qfq 已含分红，不得叠加
- 发现问题：将现金分红叠加到 qfq 回测后，总收益从 +31.67% 跳到 +102.09%（+70pp，异常）。
- 验证：茅台 2021-06-25 除权日（每股 19.293 元）qfq 价格为平滑上涨（+2.11%，无除息缺口）
  → 前复权收益已隐含分红效应；叠加现金分红属于双重计算。
- 处理：05/06 回测不叠加分红；引擎 `dividends` 参数保留，仅当改用**未复权价格**时启用。
- 数据：分红已抓 835/949 只（`scripts/12_fetch_dividends.py`），供未来"未复权+现金分红"口径或财务分析使用。
- 复核：实现未复权价格回测后（待排期）。

### D-008 定时任务崩溃：新浪 py_mini_racer 段错误
- 现象：定时任务首次运行即崩溃，日志为 V8 `partition_address_space` FATAL + py_mini_racer 栈。
- 定位：`update_kline_batch(source="sina", workers=4)` 多线程并发初始化新浪依赖的 V8 引擎 → 原生段错误，连带整个流水线退出。
- 修复：① 更新与流水线解耦（`run_daily.bat` 先跑 `02b_update_pit.py`，再跑 `10_daily_run.py --skip-update`，前者失败不影响后者）；② 默认数据源改东财 `em`，并新增 `sina_fallback=False` 开关彻底禁用新浪降级；③ `02b` 可单独运行/调试。
- 复核：2026-10-22 19:00 自动运行后检查日志与邮件。

## 2026-10-23

### D-009 风险承受度（用户决策）
- 用户经历：2500 元基金最大浮亏约 -30% 可以持有；但 10 万级别 -30% **不可接受**。
- 结论：风险预算必须按"金额"而不是"百分比"设定。若最大可承受亏损为 L，策略历史最大回撤为 D，则最大投入 ≈ L / D。
- 待定：L 的具体金额（用户需给出，如 1 万 / 2 万），据此计算可投入本金与仓位。
- 复核：实盘前。

### D-010 对超额来源的判断（用户决策）

- 处理：采用"假设是运气"的保守口径——小仓位、规则化、继续积累样本外；不因短期业绩加仓；叙事必须经过事件研究/数据验证才可交易。

### D-012 数据更新默认改用 baostock（2026-10-23）
- 现象：webapp 点"更新行情"，13 分钟只跑 100/949 只（约 7.8 秒/只）。
- 原因：东财对本机每只请求都失败 → 3 次重试（0.8+1.6+2.4 秒退避）+ baostock 兜底 ≈ 7.8 秒/只 → 全量约 2 小时。
- 处理：`02b_update_pit.py` 与 `10_daily_run.py` 默认 source 改为 `bs`（可用 `QUANTDEX_SOURCE=em` 覆盖）；实测 baostock 单源 949 只约 3~5 分钟、失败 0。
- 结果：数据已补齐到 2026-10-22（879 个文件；其余为退市/停牌股）。
- 备注：qfq 口径混用已验证连续（600905 3.44→3.36 无跳空）；长期仍需按日分区 + 全市场快照优化。
- 复核：2026-10-24 定时任务日志。

### D-013 打开即更新 + 每日一条操作记录（2026-10-23）
- 需求（用户）：① 服务一打开就自动更新一轮行情；② 每天的操作"有且仅有一条记录"，且不占空间。
- 实现：
  1) `src/data/snapshot.py`：一次请求拉全市场快照（akshare 东财），失败回退 baostock；**只在收盘后落库**，盘中不写（避免把盘中价当收盘价）。
  2) webapp 启动时自动检查数据新鲜度：过期 → 启动快照更新（失败自动回退 02b）；页面顶部显示"最新收盘日期 + 抽样更新比例"。
  3) `daily_ops` 表：主键 (date, account, action)，同一天重复运行只更新一行；webapp 新增"每日操作记录"面板。
- 加速结论：抓数瓶颈在网络（每只一次请求），不在 CPU/GPU；快照把 949 次请求降为 1 次。读面板慢是磁盘解析（900 个 parquet），按日分区迁移后可改善。
- 复核：2026-10-24（观察自动更新是否触发 + 记录是否一天一条）。

### D-014 基准指数漏更新（2026-10-23）
- 现象：报告中"沪深300"一直是 4174.53（10-19），多日未变。
- 原因：`02b_update_pit.py` 只更新 PIT 成员**股票**；`000300/000905` 是**指数**，不在股票池里，日常流程从未更新它们。
- 修复：`02b`、`10_daily_run`、webapp 的"更新行情"都增加指数更新（`update_indexes`，baostock，asset=index）；数据已补到 10-22。
- 修复后：沪深300 = 4036.30（10-22），市场状态：低于 MA20/60/200，近 20 日 -9.9%，回撤 -20.2%，宽度 10.6%。
- 复核：2026-10-24 观察报告/市场状态基准是否随日更新。

### D-015 行情存储迁移：按日分区（append-only）（2026-10-23）
- 问题：每只股票一个文件、8 年历史；每次更新整文件重写 → git 里几百个二进制变更（写放大）。
- 方案：新增 `data/store/market/daily_by_date/YYYY-MM-DD.parquet`（当天全部标的，提交 git）；
  `data/store/market/daily/` 转为本地读缓存（gitignore，可重建）。
- 迁移结果：2,866 个分区 / 1,873,566 行；600519 行数 2134 与原文件一致；933 个股票文件已从 git 移除（本地保留）。
- 更新路径：`upsert` 只把**新增行**送入缓冲区，批次结束写当天分区 → 每天只新增 1 个文件。
- 新克隆：运行 `python scripts/18_rebuild_daily_cache.py` 重建股票缓存。
- 备注：历史提交里仍保留旧数据（repo pack 约 148MB + 新对象约 200MB）；在用户机器上执行 `git gc` 可压缩。
- 复核：2026-10-24 观察一次日常更新是否只产生 1 个新区块文件。
