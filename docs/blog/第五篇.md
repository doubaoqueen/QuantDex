# 第五篇：给本地 7B 发一套工具，它真的会查——agent 落地实测

项目代号：QuantDex｜纯学习向项目，不构成任何投资建议

导读：这一篇回答一个我憋了很久的问题：本地跑的 7B 小模型，能不能当 agent 的"大脑"——我说一句话，它自己查数据、自己汇总？结论分两半：**架构能落地（实测通过），模型选型有讲究（7B 会凭记忆编代码）**。顺便记录一次我自己仪器的翻车——它教会我的东西比模型多。

## 一、起点：一个错误的认识

我一直以为"联网查询、查数据"是云端模型的专属能力，本地模型只能离线聊天。这次的认知修正从一句大白话开始：**模型从来不需要联网，需要联网的是工具。** 模型只负责"决定调哪个工具、填什么参数、怎么解读结果"，HTTP 请求由工具代码发出——akshare 从东财接口拉数据，和浏览器拉网页没有本质区别。

验证分三步：① 盘点硬件能不能养活本地模型；② 实测 tool calling 通不通；③ 7 个场景的落地测试，顺带 A/B 两个模型。

## 二、地基盘点：这张卡能养活什么

先清理：Ollama 里 5 个模型躺了 5 个月（llama2、qwen2.5 三个变体、一个微调实验品），删掉 4 个只留 qwen2.5:7b-instruct-q4_K_M，实测跑分：

- **RTX 5070 12GB**：7B 的 Q4 量化版（4.7GB）**100% 进显存**，生成速度 110 tok/s，热运行 2.6 秒出一段 200 字回答
- 新闻打分实测一次通过：回购公告 → `{"polarity":"利好","event_type":"回购"}`，JSON 零差错
- 一个显存租赁常识：这张卡上还住着另一个项目的 Qwen3-VL 服务（vLLM，占 9.7GB）——**Ollama 的 4.7GB 和它装不下同一张卡**。两张"模型"是租户，用谁开谁。

顺手验证了 WSL 里的 vLLM 服务在今天的显存基线下还能不能起（0.88 档起不来，降到 0.86 稳定，已回写那边的操作手册）——这是题外话，但它提醒我：**显卡不是静态资源，基线会漂移，任何"占 9.6GB"的承诺都要用当天的实测背书。**

## 三、第一轮实测：全绿？不，是我的仪器坏了

我搭了一个 50 行的 agent 循环 + 3 个封装工具（akshare 的个股新闻、实时行情、沪深300 权重表），跑了 7 个场景。结果一多半"失败"——新闻工具全报 `Invalid regular expression`，行情工具全报 `Connection aborted`。

去查 akshare 才发现：**这两个接口在我机器上本来就是坏的**（新闻接口死于 py_mini_racer 的 JS 正则——和此前禁用新浪降级是同一族问题；行情接口死于东财断连——就是控制台日志里连续出现的那一个）。唯一健康的接口（中证指数公司）对应的场景满分：模型一次调用、参数正确、精确解读了返回 JSON。

**教训一：怀疑结论之前，先怀疑测量仪器。** 模型还没被测试，测试先被脏工具污染了。这和回测里"数据错了结论全错"是同一件事——所以第四篇说先冻结研究再做体检，这里说先修工具再做 agent。

## 四、第二轮：一个更隐蔽的 bug——模型开始"表演调用工具"

修完工具层重跑，结果更诡异：7 个场景里模型**一次工具都没调用**，全在纯文本回答。最吓人的是 S1——它输出"工具返回结果为：中国平安权重 5.51%……"，一份**看起来完全合理、但纯属编造**的权重表（真实的 weight-first 是贵州茅台 3.836%）。

排查到半夜才发现：是我重写探针时把 `tools` 参数弄丢了——**模型从头到尾没收到工具定义，它在"裸答"**。它甚至配合地演出"我将使用工具……工具返回……"的完整戏码。修一行代码，同一请求重跑 10 次：工具触发 10/10，确定性没问题。

**教训二：模型会表演调用工具。** 没收到工具定义时，它不会说"我没有工具"，而是顺着话头编一份结果——因为训练数据里这样的对话太多了。agent 循环必须把"工具列表确实发出了"当成自己的责任，模型不背这个锅。

## 五、判定数据：7 场景 A/B

修好仪器后的干净成绩（同一套场景、同一套工具，只换模型）：

| 场景 | qwen2.5:7b | qwen3:8b |
|---|---|---|
| S1 单工具+参数 | ✅ | ✅ |
| S2 本地行情+解读 | ✅ | ✅ 表格更规整 |
| **S3 两步链**（权重第一→查它行情） | ❌ **没查权重表，凭记忆猜了 600000** | ✅ 先查权重表→再查行情，两步完整 |
| **S4 名称→代码** | ❌ 中际旭创记成 300533 | ✅ 正确解析 300308 |
| S5 幻觉抗性（菜单外问题） | ✅ 不编造 | ✅ 且回答更干脆 |
| S6 错误处理（无效代码） | ✅ | ✅ 带诊断建议 |
| S7 超出工具范围 | ✅ 诚实拒绝 | ⚠️ 空回答（唯一小瑕疵） |

两个失败场景是同一类病的两个症状：**让模型凭"参数记忆"填实体**。7B 对"中际旭创的代码是什么"这种事毫无把握，但它不会承认——它会给你一个自信的错答案。qwen3:8b 在 S3 里展示了正确的两步链（先调权重工具，拿到代码再查行情），这就是"新一代"的真实差距，不在文采在锚定。

**教训三：参数记忆是 agent 最危险的便利。** 凡是工具能查的实体（代码、名称、日期），一律禁止模型凭记忆填——加一个 `resolve_symbol` 工具 + 一条规则就解决了。

## 六、三条工程铁律

1. **工具菜单必须窄。** akshare 有 1000+ 接口，全暴露给 7B 等于让它开卷考试还允许编答案。只封装 3-5 个项目真用的工具，参数 schema 写死。
2. **错误熔断放循环层。** 模型遇到工具报错会固执地用相同参数重试 6 次。循环里加一个判断：同参数失败过一次，注入"禁止重试"——它立刻改道或如实报告。
3. **实体解析走工具。** 见 S3/S4。规则一句话："使用标的代码前必须先用工具查询，禁止凭记忆填写。"

## 七、排期决定：把闸门用在自己身上

这次验证让我兴奋了一晚上（真的跑通了！），但兴奋不能绕过自己的闸门。agent 在 QuantDex 里的真实岗位是**新闻/公告管线的取数层**——而那条管线的前置（数据源选型、公告因子验证）还没开工；关键路径上还站着 11 月 20 日的影子盘四周归因。所以决定：**agent 排进 TODO，排在新闻管线之后**，探针脚本存档在 `docs/blog/attachments/agent_probe.py`，开工时直接改造。兴奋的正确打开方式是排期，不是加班。

## 八、核心代码

agent 循环的全部（工具注册 + 熔断 + 多轮），完整可运行版见 `docs/blog/attachments/agent_probe.py`：

```python
# ---- 工具注册：菜单只有 3 个，schema 写死 ----
TOOLS = [
    {"type": "function", "function": {"name": "get_stock_news",
        "description": "获取某只 A 股个股的近期新闻列表",
        "parameters": {"type": "object", "properties": {
            "symbol": {"type": "string", "description": "6 位股票代码"}},
            "required": ["symbol"]}}},
    # ... get_quote / get_index_top_weight 同构，略
]

def run_tool(name, args):
    fn = DISPATCH.get(name)                      # DISPATCH = {'get_stock_news': t_news, ...}
    if fn is None:
        return {"error": f"未知工具 {name}"}      # 菜单外调用直接拒
    try:
        return fn(**args)
    except Exception as e:
        return {"error": str(e)[:200]}           # 错误也回填给模型，让它自己决定下一步

# ---- agent 循环：模型吐 tool_call → 执行 → 结果回填 → 再来 ----
def agent(query, max_iters=6):
    msgs = [{"role": "user", "content": RULES + "\n\n" + query}]
    fail_sig = {}                                # 熔断：同参数失败过一次就禁重试
    for _ in range(max_iters):
        m = chat(msgs)                           # POST /api/chat，带 tools=TOOLS
        if not m.get("tool_calls"):
            return m.get("content")              # 模型认为信息够了 → 最终回答
        msgs.append(m)
        for call in m["tool_calls"]:
            fn, args = call["function"]["name"], call["function"]["arguments"]
            sig = json.dumps([fn, args], sort_keys=True)
            result = ({"error": "该调用已失败一次，禁止重试"}
                      if fail_sig.get(sig) else run_tool(fn, args))
            fail_sig[sig] = 1
            msgs.append({"role": "tool", "content": json.dumps(result, ensure_ascii=False)})
```

就这些。没有框架、没有 LangChain——一个 while 循环加一个字典。

## 九、收个尾

这一篇没有产生任何收益：agent 排期在后面，模型还有小瑕疵，新闻管线八字没一撇。它产生的是**确定性**——本地模型 + 工具调用这条路的每一步坑（仪器污染、表演式调用、参数记忆幻觉、显存租赁），都已经被我踩过并记下了。等排期轮到它时，不用再摸黑。

**大平台把这条路包装成产品卖钱；我把它的每一个坑写成博客。这大概就是个人量化的全部体面。**
